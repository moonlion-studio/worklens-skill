# 真人理解与复述验证

报告质量与使用者能力提升是两项不同验证。本文件提供后续验证方法，不代表已经完成真人测试。

选使用者确实参与过的一项任务，保留原始需求、实际改动和验收材料。先请使用者不用报告讲约两分钟，记录以下四点是否能讲清：

1. 问题所属领域，以及一个术语对应的真实机制。
2. 当前方案为何适用，一个相关替代方案或风险。
3. 什么已经验证、什么还不能下结论；指标怎样采集。
4. 自己和 AI 分别做了什么。

读 WorkLens 报告后，关闭报告，用同样四个问题复述，再增加一个此前没出现的情景，例如网络超时、权限变化或数据更新，观察能否迁移解释。次日再次短讲，区分即时照读与保留理解。

每点记录为“可独立解释/需提示/仍有关键错误”，同时保留原话与事实依据。若由模型协助评分，应由人核对关键事实，不把模型评分自动当专家结论。

同时记录阅读/修改报告耗时、错误术语、需要人工补证的内容和实际使用意愿。在多个用户、多个真实任务中重复，才能更有依据地判断工具是否缓解痛点；不以报告篇幅、模型输出次数或主观满意度替代这些结果。
