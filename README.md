# WorkLens｜工作价值解读器

**把 AI 协作中做过的工作，转化为讲得清、可核验的专业理解与面试表达。**

WorkLens 是一个面向 AI 协作开发者的 Skill。它在原任务交付后，结合实际需求、改动与验证记录，解释这是什么领域的问题、采用了哪些专业机制、方案如何取舍、结果能证明到哪一步，并生成面试回答、工作汇报和理解追问。

当前作为预览版发布：输出需要使用者核对事实；本机小模型测试已发现补写证据和概念混淆等问题，具体记录见测试报告。生成报告不等于使用者已经掌握相关能力。

适合需要用自然语言推动开发，同时希望积累技术/产品理解、项目证据和职业表达的人。覆盖 AI 应用工程师、B 端产品经理及项目交付等视角，叙述随实际岗位调整。

## 解决什么问题

你知道自己让 AI 增加了什么功能，却难以回答：这属于什么专业领域？为什么这样设计？改善了哪个环节？怎样衡量？自己负责了什么？面对追问能否解释？

WorkLens 把这些问题接到每次真实任务后面，在细节还没有丢失时留下解释与证据。它提供学习和复述输入；是否真正掌握仍需要使用者自己回答追问。

## 一次交付会得到什么

| 内容 | 输出 |
|---|---|
| 问题定位 | 原任务、涉及角色/业务对象、问题所属领域 |
| 专业概念 | 少量恰当术语，以及它们在本次改动中对应的机制 |
| 方案判断 | 当前做法、适用边界、风险和相关取舍 |
| 结果证据 | 已实现、已验证、已发布和实际收益分别到哪一步 |
| 指标口径 | 有数据时计算；缺数据时给出最小采集办法 |
| 个人贡献 | 使用者、AI 和其他参与者的实际责任及待确认项 |
| 职业表达 | 约 30–60 秒面试回答、简明工作汇报、1–2 个追问及回答要点 |

复杂任务展开，小样式修改简短解释。报告在一次有实质产出的交付后生成，不重复出现在每条进度消息里。

## 两种使用方式

### 完成任务并解释

```text
使用 $work-impact-debrief 调整这个预约提交问题。
完成后说明问题领域、专业机制、取舍、验证结果，
再给我 AI 应用工程师面试和工作汇报的讲法。
```

原任务的实现、测试和发布权限仍按原要求执行。Skill 不自动扩大改动范围。

### 复盘已有改动

```text
使用 $work-impact-debrief 分析这份 diff 和交付记录。
只生成专业解读，不修改程序，不发布。
重点解释个人贡献、业务变化和还缺哪些证据。
```

已有明确岗位时直接沿用；没有足够材料时先给有边界的初稿，再提出少量关键补充问题。

## 示例：一句自然语言任务怎样被展开

输入：

> 批量导入供应商 CSV 时，别一条失败后就不知道哪些已经写进去了。

假设交付材料显示：导入前逐行校验并给出错误行报告，合法批次使用事务写入，以外部编码识别重复记录，并保留批次状态。

专业解读可以解释为：**批次处理、输入校验、事务原子性、幂等和可观测性**。每个概念都应对应上述具体机制。

如果只完成了本地构造数据验证，就明确该验证范围；没有真实耗时对照，就提出采样口径，不填写效率提升比例。面试回答进一步说明如何避免部分写入不可追踪、重复请求如何处理，以及实际由谁完成判断和验证。

示例均为构造教学场景，不代表任何原公司的业务数据或收益。

## 安装到 Codex

在已下载的仓库根目录运行：

```bash
mkdir -p "${CODEX_HOME:-$HOME/.codex}/skills/work-impact-debrief"
cp -R ./SKILL.md ./agents ./references "${CODEX_HOME:-$HOME/.codex}/skills/work-impact-debrief/"
```

如果已经安装了同名 Skill，先比较版本与本地修改，再合并文件。随后在新会话中使用 `$work-impact-debrief`。

如需将相关任务的专业解读设为长期习惯，可将下面的约定合并到已有的全局或项目 `AGENTS.md`，保留原有内容：

```text
完成有实质改动的开发、修复、流程优化或评测任务后，
使用 work-impact-debrief 解释问题领域、机制、方案取舍、
指标证据与个人贡献，并给出面试/汇报表达和理解追问。
简单改动简短讲解；无关任务不附带报告。
```

只有获得保存授权时才写入长期档案。导入其他助手时，需要对方支持并实际加载相应指令；本仓库没有宣称全平台兼容。

## 证据与数据原则

- 使用专业术语时解释其实际对应，不补不存在的架构、算法或实验。
- 本地验证、开发包上传、正式发布、真实使用及业务收益分别表述。
- 规则满足率、回答正确率、引用支持率、结构合法率和业务任务完成率分开衡量。
- 没有基线就先建立基线，不生成虚构的增长率或降本数字。
- 个人贡献按实际要求、判断、实现和复核记录，不把 AI 提出的方案自动归给使用者。
- 保存报告、查询生产、发送消息和发布代码遵循原授权；Skill 不持续监听电脑。

## 测试与适用边界

测试设计、原始输出和逐例人工检查见 [EVALUATION.md](EVALUATION.md)。测试材料使用构造场景，且不直接复制原业务资料。

可阅读一份[人工核对后的讲解样例](eval/EXPECTED_EXAMPLE.md)。该示例单独标注，不冒充模型原始输出，也不计入自动生成通过数。

报告生成测试可以检查术语解释、指标口径和事实边界；它不能单独证明使用者的面试表现、理解程度或录用结果有所提升，也不覆盖实际工具执行与所有宿主的自动触发行为。

复跑方法见 [eval/README.md](eval/README.md)。无需为了使用 Skill 安装测试模型；本机模型只是这次可复现的测试后端。
